# Lane G: independent evaluation harness (notes)

Lane G evaluates the lanes only through `lanes/<lane>/predict.py:get_predictor()` and the full `seen.pipeline`. It never imports their training code. Every number in `docs/eval_report.md` is regenerated by `python eval/run_all.py --remote` (from the Mac) or `python -m eval.run_all` (on the box GPU1).

## 1. Shared tooling (for every lane)

| file | what it gives you |
|---|---|
| `eval/stats.py` | `wilson_ci`, `prop_metric(name, k, n)` (Wilson 95%), `bootstrap_ci` / `boot_metric` / `mae_metric` (percentile bootstrap over images, clips or videos), `ece`, `reliability_bins`, `accuracy_coverage`, `confusion`, `average_precision` / `detection_ap` (AP@IoU with an image-level bootstrap), `detection_recall`. They return dicts shaped like `contracts/metrics.schema.json#/$defs/Metric`. |
| `eval/manifest.py` | Held-out manifests `eval/manifests/<component>.jsonl` with fields {id, path, source, dataset, split, phash, label}. It also provides: its own 64-bit DCT pHash (the same algorithm as `imagehash.phash`, so the Mac and the box agree; videos are hashed as 5 frames); `dedup` across datasets; `split_by_source`, which joins sources linked by near-duplicates and puts near-duplicates of test items in "quarantine"; and the trainer API `excluded_ids`, `excluded_paths` and `filter_train(paths, components)`. The leakage audit is `python -m eval.manifest audit --train-list runs/<lane>/<exp>/train_files.txt`. |
| `eval/report.py` | Collects `docs/lanes/*_results.json` plus Lane G's own files. It validates every entry against the schema (invalid entries are listed, never silently dropped) and writes `docs/eval_report.json`, `docs/eval_report.md` and `web/public/eval_report.json`. Real and synthetic results go in separate sections. |
| `eval/failures.py` | Failure gallery. Takes the images in `docs/lanes/failures/<lane>/` (plus an optional `failures.json` with descriptions) and the jury failures, applies three face-blur passes (`seen.blur` person heads, OpenCV YuNet, Haar frontal+profile), resizes to ≤ 640 px and writes `docs/lanes/eval_gallery/`. |
| `eval/bench.py`, `eval/cost.py`, `eval/jury_run.py`, `eval/run_all.py`, `eval/modal_bench.py` | Speed, cost, jury set, one-command regeneration, and the same benchmark on a Modal L4. |

Requests to lanes (sent to the integrator):
1. Write the training file list (one path per line) to `runs/<lane>/<exp>/train_files.txt`. `run_all` audits it against every held-out manifest.
2. Optionally add `docs/lanes/failures/<lane>/failures.json` describing each failure image.

## 2. Jury-style test set (`eval/jury/`)

- 96 inputs: 82 Wikimedia Commons photos, 7 short Commons videos (5–80 s; the first 60 s are used, sampled at 2 fps and capped at 1280×720 like the browser), and 7 frames cut from those videos.
- Every input has its licence, author and file page in `eval/jury/jury.jsonl`. Licences:
  - CC BY-SA 4.0: 49
  - CC BY 4.0: 10
  - CC BY 2.0: 7
  - CC0: 6
  - public domain: 6
  - other CC BY / BY-SA versions: 11
- Content (categories in `jury.jsonl`):
  - Uzbek and Central Asian cars, plus BYD/Toyota (15)
  - motorcycles, mostly Ducati, plus a scooter in Tashkent (6)
  - street scenes (3), parking and barrier gates (8)
  - garages and lifts (9), car washes (6)
  - close-ups: wheels, flat tyres, damage, plates (9)
  - night and rain (7)
  - non-car: people, plov, Registan, a cat, a bazaar, an office queue (9)
  - documents: newspaper, ID-card specimen (2)
  - "tricky" items (8): stamp, chart, ad drawing, toy cars, postcard drawing, locomotive from above, locomotive on lift jacks
  - videos (7) and video frames (7)
- Expected behaviour per input:
  - primary scene plus the list of acceptable scenes
  - vehicle present (yes/no)
  - plate visible (yes/no)
  - inspection target (yes/no)
  - hard (yes/no)
  - a one-line description
- Expected modules are derived from these labels by the product spec in `eval/jury/common.py:expected_modules`, independently of `seen/router.py`.
- Totals: 67 inputs with a vehicle, 17 with a visible plate, 21 where the right answer is "unknown", 22 marked hard.
- Labels: one annotator, the Lane G agent, working from contact sheets and one frame per video. The record is `eval/jury/curate_v1.py`; sampling is `eval/jury/select.py`.
- The set is held out in `eval/manifests/jury.jsonl` (pHashes). Lanes that use Commons stills, e.g. lift photos, must run `filter_train(..., components=["jury"])`.
- Media: `data/raw/eval_jury/` on the box, staged to the NVMe at `/home/amirkhon/seen_fast/eval/jury/` (0.3 GB).

## 4. Known limits

- The jury labels are a single annotator's judgement. Ambiguous inputs have several acceptable scenes, and hard cases are reported separately.
- The plate check on the jury set only tests whether *some* text was read when a plate is visible. Text correctness is the job of Lane A's OCR test.
- Speed was measured on an RTX PRO 5000 Blackwell (box GPU1). That GPU is shared, and the HDD was IO-saturated on 10 Oct, which inflates cold-start times. The edge-box (RTX 4060 Ti) numbers are **proxy estimates** from spec ratios, not measurements. A Modal L4 run (`eval/modal_bench.py`) is ready but has not been run, because no Modal token is configured.
- The stream test feeds pre-decoded frames. Video decode (NVDEC) and network ingest are not included.

## 5. Status / changelog

- 2026-10-10: tooling, jury set v1 and manifests were built. The first "before" runs used the baseline pipeline: RF-DETR-base COCO + fast-alpr global.
- Runs under the HDD stall were discarded and re-run on the NVMe env. Those include a 15-min import stall and an 881 s pipeline load.
- Lane predictors (`get_predictor` / `get_router`) were not speed-benchmarked yet. Loading SigLIP2 blocked on a Hugging Face cache lock held by another job. Re-run: `python eval/run_all.py --remote`.
- Leakage findings:
  - 9 jury items are in the flow/ops Commons pools.
  - 3 jury items are backgrounds in ident's synthetic plate composites (ident/det_full).
  - All 12 are excluded from the "_clean" jury metrics, and the lanes were asked to `filter_train(..., ["jury"])`.
